## Usage in MDL

```sql
-- React pluggable widgets
PLUGGABLEWIDGET 'com.mendix.widget.custom.badge.Badge' badge1

-- Legacy custom widgets
CUSTOMWIDGET 'com.company.OldWidget' legacy1
```

## When these files are not enough

They are a snapshot: a widget upgraded since the last `refresh catalog` is
described here as it was, not as it is. For the same data read live from the
`.mpk`, plus the dynamic visibility rules that are not rendered here at all:

```bash
mxcli widget describe <name> -p <app.mpr>    # e.g. datagrid, combobox
mxcli widget list -p <app.mpr>               # every widget, one line each
```

Prefer `describe` when a property does not behave as this file says it should.

## Widgets without child-block routing

mxcli has no MDL child-slot mapping for these, so their example is the widget
line alone. For a leaf widget (a filter, an input) that is simply correct. If
one of them needs a `{ … }` block, the example will not tell you — check
`mxcli widget describe <name>` for properties of type `widgets` or `object`:

- `datagriddatefilter`
- `datagriddropdownfilter`
- `datagridnumberfilter`
- `datagridtextfilter`
